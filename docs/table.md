| Trecho | O que faz | Por quê |
| --- | --- | --- |
| CREATE OR REPLACE FUNCTION fn_audit_log() RETURNS TRIGGER | Declara uma função PL/pgSQL especial do tipo TRIGGER, que não recebe parâmetros explícitos — ela recebe variáveis implícitas (NEW, OLD, TG_OP, TG_TABLE_NAME) fornecidas pelo PostgreSQL no momento da execução do gatilho. | Uma única função genérica serve para todas as tabelas monitoradas, evitando duplicar lógica (princípio DRY). |
| current_setting('app.usuario_id', true) | Lê uma variável de sessão chamada app.usuario_id, definida via SET LOCAL app.usuario_id = '...' dentro da mesma transação (implementado na Fase 2, na dependency de autenticação). O segundo parâmetro true evita erro caso a variável não tenha sido definida (retorna NULL em vez de lançar exceção). | É assim que a trigger do banco "sabe" quem fez a alteração, já que o PostgreSQL não tem acesso nativo ao usuário autenticado da aplicação. Atende RF06.2 ("usuário responsável pela ação"). |
| Bloco BEGIN...EXCEPTION WHEN OTHERS | Camada extra de segurança: se por algum motivo o cast para uuid falhar (ex: variável mal formatada), a função não quebra — apenas grava usuario_id = NULL. | Evita que uma falha na propagação do usuário impeça o registro em si (alinhado ao espírito de resiliência do RF12, embora aqui seja apenas uma salvaguarda local). |
| IF TG_OP = 'INSERT' / 'UPDATE' / 'DELETE' | TG_OP é uma variável automática que informa qual operação disparou o trigger. Cada ramo monta dados_anteriores e dados_novos de forma coerente com a operação: - INSERT: só há estado novo. - UPDATE: há estado antes (OLD) e depois (NEW). - DELETE: só há estado anterior (OLD). | Atende diretamente RF06.1/RF06.2 e a especificação do UC01-UC06, que pede "estado completo antes/depois via row_to_json" (aqui uso to_jsonb, equivalente moderno e mais eficiente — guarda como jsonb em vez de json texto puro, permitindo indexação e consultas futuras). |
| to_jsonb(NEW) / to_jsonb(OLD) | Converte a linha inteira da tabela (todas as colunas) em um objeto JSON binário. | Captura o "estado completo", sem precisar listar campo por campo — funciona para qualquer tabela, reforçando a genericidade da função. |
| v_registro_id := NEW.id / OLD.id | Extrai o identificador do registro afetado. | Necessário para a coluna registro_id de audit_log, permitindo rastrear o histórico de uma entidade específica (requisito do UC10 - consulta por filtros). |
| INSERT INTO audit_log (...) | Grava efetivamente o log, dentro da mesma transação da operação de negócio (characterística de trigger AFTER). | Isso é o que garante, por enquanto (Postgres único banco), a atomicidade: se a transação de negócio falhar, o log também não é gravado (rollback conjunto); se a transação for commitada, log e dado vão juntos. Atende RF06.1. |
| RETURN OLD / RETURN NEW | Toda função de trigger de linha precisa retornar um registro. Para DELETE, retorna OLD; para os demais, NEW. | Exigência de sintaxe do PostgreSQL para triggers do tipo ROW. |
